# Step 18 — Automated API tests (manual test guide)

**Goal:** Confirm Vitest API tests run against a dedicated `fms_test` database (or embedded Postgres if local Postgres is down) and cover auth/tenant isolation, dynamic fields, expense CRUD, and income + net balance.

**Maps to:** Phase 1–6 testing (FMS-10, FMS-19, FMS-29, FMS-52)  
**Depends on:** Steps 01–17 (existing APIs; no new HTTP routes)

**Artifacts:**  
- Markdown: `docs/manual-test-guides/step-18-automated-tests.md`  
- PDF: `docs/manual-test-guides/step-18-automated-tests.pdf`  
- Server: `cd server && npm test`  
- No new HTTP APIs (Postman collection unchanged)

---

## Prerequisites

- [ ] Steps 01–17 already implemented
- [ ] `server/.env.local` exists with `DATABASE_URL` and `JWT_SECRET` (min 32 chars)
- [ ] PostgreSQL running **or** allow the test harness to start embedded Postgres (used automatically if `localhost:5432` is down)

---

## Setup commands

From `finance-management/server`:

```bash
npm install
npx prisma generate
npm test
```

Watch mode (optional):

```bash
npm run test:watch
```

Tests rewrite `DATABASE_URL` to database **`fms_test`**. They never truncate `fms_dev`. If local Postgres is unreachable, the harness starts a temporary embedded Postgres on a high port.

## Negative / safety notes

- Tests **refuse** to run if `DATABASE_URL` does not point at `fms_test` (`assertTestDatabaseUrl`).
- `server/.env.test` is generated by the harness and gitignored.
- First run with embedded Postgres may take ~30–60s while the cluster initialises.

**When all required items pass:** mark Notion tasks **FMS-10**, **FMS-19**, **FMS-29**, **FMS-52** Done. Remaining product item: secure storage hardening (**FMS-23**, Step 19).
